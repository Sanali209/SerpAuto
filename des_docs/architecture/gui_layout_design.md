# Дизайн-документ: Графический интерфейс "Serpentine GUI" (Cognitive Debugger)

## 1. Архитектурная Философия GUI

В движке Serpentine графический интерфейс — это не монолитная оболочка, в которую зашит код, а независимая наблюдательная система (**`GUIDebugSystem`**).

**Главные принципы:**

* **Zero-Overhead (Нулевое влияние на логику):** GUI не выполняет логику агентов. Он только *читает* состояние ECS-реестра (`World`) и отправляет команды управления в главный цикл. Если систему GUI отключить, движок продолжит работать с той же логикой.
* **Immediate Mode (DPG):** Построен на **DearPyGui (DPG)**. Интерфейс рендерится напрямую на GPU со скоростью 60+ FPS, не блокируя асинхронный цикл Python (`asyncio`), в котором "думают" агенты.
* **Auto-Generation (Zero-code UI):** Никакого хардкода виджетов для новых фичей. Интерфейс строится динамически за счет рефлексии (парсинга `Pydantic`-схем компонентов и узлов).

---

## 2. Компоновка Рабочего Пространства (Docking Workspace)

Используется система плавающих и прилипающих окон (Docking Space), аналогичная Unreal Engine или Blender. Viewport (главное окно ОС) разбит на логические зоны, которые разработчик может перетаскивать, группировать и сохранять в `.ini` файл.

### Глобальный Layout (По умолчанию):

1. **Top Bar:** Control Deck (Управление временем и режимами).
2. **Left Panel:** World Outliner & Component Inspector (Хирургия памяти ECS).
3. **Center Panel:** Perception Monitor (Глаза агента / Внутренний рендер).
4. **Right Panel:** Pipeline Node Editor (Конструктор конвейера восприятия).
5. **Bottom Panel:** Behavior Tree Tracer & Action Queue (Отладка мозга и экшенов).
6. **Floating/Tabbed:** Swarm / Message Broker Monitor (Сеть роя).

## 3. Детальное описание панелей (Модули DPG)

Этот уровень детализации превращает DPG-интерфейс из простой «смотрелки» в полноценный редактор движка (как Unity Editor). Вся архитектура строится на системе **Docking Space**. Каждый модуль — это отдельное окно `dpg.add_window()`, которое можно оторвать, перетащить, прикрепить сбоку или объединить во вкладки.

### 3.1. Control Deck (Машина Времени)
Панель приклеена к верхнему краю экрана. Управляет "сердцем" движка — тиковым циклом `SerpentineEngine`.
* **Транспорт:** `[▶ Play]` / `[⏸ Pause]` / `[⏹ Stop]` / `[⏭ Step]` (сделать ровно 1 тик и замереть).
* **Управление скоростью:** Ползунок `Tick Rate Limit`.
* **Переключатель режимов:** `[Architect | Teacher | Gymnasium | Headless]`.
* **Телеметрия:** Текстовая строка состояния (Tick, Entities, TPS).

### 3.2. World Outliner (Менеджер Сущностей)
Это окно отвечает за CRUD-операции над сущностями в реестре `World`.
* **Визуализация:** Иерархический список (`dpg.add_tree_node`). Движок каждый тик (или по событию) синхронизирует список с `world._entities`.
* **Добавление (Spawn):** Вверху окна есть кнопка `[+ Add Entity]`. При нажатии создается пустой `UUID`.
* **Удаление (Destroy):** Иконка `[🗑️]` удаляет сущность (`world.remove_entity(id)`).
* **Тегирование:** Ищет у сущности `AgentMetaComponent` или `UIElementComponent` и подменяет UUID на `🤖 Scraper_Agent` или `📦 Login_Button`.
* **Механика выбора:** При клике на строку её ID уходит в `selected_entity_id`, что мгновенно перестраивает окна Инспектора, Мозга и Восприятия.

### 3.3. Component Inspector (Авто-генерация GUI)
Это окно — сердце "нулевого кода". Всегда показывает «внутренности» сущности из `selected_entity_id`.
**Жизненный цикл отрисовки:**
1. **Событие выбора:** Пользователь кликнул на сущность.
2. **Очистка:** DPG удаляет все старые виджеты.
3. **Чтение:** `GUIDebugSystem` запрашивает у `World` все компоненты этой сущности.
4. **Рефлексия:** Парсинг Pydantic `model_fields`.
5. **Генерация:** Перевод типов (`int`, `bool`, `Enum`) в DPG-виджеты (`drag_float`, `checkbox`, `combo`).
6. **Data Binding:** `callback` делает `setattr(component, field_name, new_value)`. Изменения улетают в оперативную память движка мгновенно.

**Добавление/Удаление Компонентов:**
Выпадающий список `[Select Component Class...]` и кнопка `[+ Add Component]`. Возле каждого активного компонента есть `[X]` для удаления.

### 3.4. Perception Viewer (Настройка Восприятия)
Работает с `PerceptionComponent` выбранной сущности. У агентов — «глаза», у UI — распарсенные данные.
* **Визуальный стрим (Texture View):** Если есть ссылка на кадр (скриншот/Змейка), рендерит `dpg.add_image`.
* **Данные реального времени (JSON Tree):** Под картинкой выводится древо `raw_context` для LLM.
* **Сценарий работы:** Заметив `null` в распарсенном JSON (например, цена товара), разработчик переходит в Pipeline Editor, правит XPath и на следующем тике видит исправленные данные.
* **Дебаг-слои (Overlays):** Чекбоксы (YOLO Bounding Boxes, Passability Grid).

### 3.5. Brain & Memory Editor (Вмешательство в Разум)
Дает "God Mode" над логикой LLM и Behavior Tree.
* **Редактор Blackboard:** Таблица Key-Value. Позволяет вручную править убеждения агента на лету.
* **LLM Prompt Preview:** Только чтение. Показывает финальный, склеенный промпт перед отправкой в сеть.
* **История (Episodic Memory):** Лог последних действий. Кнопка `[+ Add Memory]` для ручной корректировки "памяти".

### 3.6. Action Queue & Swarm Broker
* **Action Queue:** Визуализация `ActionBufferComponent`. Карточки с кнопками `[X]` для отмены экшенов до выполнения и `[+ Inject Action]` для ручного внедрения команд.
* **Live BT Graph:** Трассировщик дерева поведения (только чтение).
* **Swarm Sniffer:** Бегущий лог сети сообщений и матрица роевого трафика.

## 3.7. Архитектура Связей Окон (Data Flow в GUI)

Вся магия DPG заключается в том, что эти окна не общаются друг с другом напрямую. Они общаются только через `World`:
1. В окне **Component Inspector** дергается ползунок (скорость `dx` с 0 на 5).
2. Callback напрямую меняет Pydantic-объект в `World`.
3. На следующем тике `PhysicsSystem` двигает агента на `x + 5`.
4. Окно **Perception Viewer** (просто читающее координаты) перерисовывает агента на новой позиции.
Такой подход гарантирует, что можно закрыть любое док-окно, и логика движка не сломается.



### 3.5. Pipeline Node Editor (Конструктор Восприятия)

Правая панель. DAG-редактор для сборки конвейера обработки данных (Компьютерное зрение или парсинг DOM).

* **Рабочее поле:** Холст для перетаскивания узлов фильтров (`Screen Capture` -> `Crop` -> `YOLO` -> `OCR`).
* **Auto-UI Конфиги:** Внутри каждого узла автоматически генерируются ползунки настроек (см. раздел 4).
* **Preview Pins (Глазок):** У каждого узла есть кнопка `[👁️]`. Нажатие на нее переключает центральный `Perception Monitor` на вывод картинки/данных именно с этого этапа конвейера для точной калибровки (например, настройки `confidence_threshold` для YOLO).

### 3.6. Swarm Message Broker (Радар Роя)

Плавающее окно для дебага многоагентной связи (Pub/Sub).

* **Traffic Visualizer:** Матрица обмена сообщениями.
* **Live Sniffer (Лог сети):** Бегущая консоль: `[Tick 450] Agent_Parser -> (Broadcast: target_found) -> Payload: {"price": 650}`. Клик по строке открывает полный JSON.
* **Dead Letter Warning:** Красные алерты, если агент шлет сообщение в топик, на который никто не подписан.

## 4. Магия "Авто-Интерфейса" (Техническая реализация рефлексии)

Чтобы не писать код UI вручную для каждого нового компонента или фильтра, `GUIDebugSystem` использует кодогенерацию "на лету" из `Pydantic`.

**Алгоритм (`auto_ui_builder.py`):**

1. Читает `model_fields` любой Pydantic-схемы (например, `CannyFilterConfig`).
2. Для `type == int` (с `ge=0, le=255`) ➡️ `dpg.add_slider_int(min_value=0, max_value=255)`.
3. Для `type == bool` ➡️ `dpg.add_checkbox()`.
4. Для `type == Literal["RGB", "HSV"]` ➡️ `dpg.add_combo(items=["RGB", "HSV"])`.
5. **Data Binding:** К каждому виджету привязывается `callback`. Изменение ползунка в UI мгновенно мутирует поле в объекте `config`, и на следующем тике фильтр или агент используют уже новое значение.

## 5. Инструменты Персистентности (Сохранение в GUI)

В меню **File** интегрированы механизмы работы со стейтом (из ECS):

* **💾 Save / Load Blueprint:** Сохраняет топологию Pipeline Editor и структуру Behavior Tree в `blueprint.json`. Используется для переноса настроенного агента на сервер в Headless-режим.
* **📸 Snapshot World State:** Делает полный дамп `World` (все Entity и Components) в JSON-файл.
* **⏪ Time Travel (Load Snapshot):** Ставит движок на паузу, очищает текущий мир и загружает сохраненный снимок. Позволяет мгновенно воссоздать ситуацию, в которой агент словил баг.
* **⚙️ Save UI Layout:** Сохраняет размеры и докинг окон в `dpg_layout.ini`.

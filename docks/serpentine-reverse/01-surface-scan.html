💡 Ключевые концепции

1. Strategy Pattern для режимов

Каждый режим (Architect, Production, Gymnasium, Teacher) — отдельный класс ModeStrategy, определяющий набор систем для каждой фазы. Позволяет переиспользовать системы между режимами.

2. Decorator-based Registry

Компоненты, системы и BT-ноды регистрируются через декораторы (@Registry.register_component, @Registry.register_system, @Registry.register_node). Registry хранит метаданные (фаза, режим, приоритет, tick_rate) для интроспекции.

3. Fixed vs Variable Timestep

Системы могут иметь собственный tick_rate — фиксированный шаг по времени с аккумулятором, независимо от TPS движка. Engine поддерживает Play/Pause/Step.

4. Intent → Action Pipeline

Модуль Mind (BT) генерирует Intents → ActionBufferComponent (очередь) → ActionExecutionSystem (PyAutoGUI). Двойные очереди (action/shadow) для imitation learning.

5. Event Bus Decoupling

GUI ↔ Engine коммуникация через EventBus (паттерн pub/sub). GUIEventBus для UI-событий (Play/Pause, клики по viewport).

6. Pydantic-first Data Layer

Все компоненты, сообщения, наблюдения — Pydantic BaseModel с валидацией. Есть fallback без Pydantic.

7. Auto UI Builder

AutoUIBuilder генерирует DearPyGui-виджеты из Pydantic-моделей (поля типов str/int/float/bool/Enum → input/drag/checkbox/combo).
